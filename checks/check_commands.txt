$ rec --help
usage: rec [-h] [--project P] {project,experiment,tree,add,set,open,run,end,stop} ...

Adds or changes a project, an experiment or a record (a decision, finding,
protocol rule or question) in the lab's database, starts or ends a run, or
prints the experiment tree. rec COMMAND --help prints COMMAND's paragraph
below, and the one that applies to every command.

usage: rec project NAME --text DESCRIPTION [--folder F] [--files F] [--views FILE ...] [--replace]
       rec experiment NAME --text DESCRIPTION [--in PARENT [--move]] [--dead-end | --no-dead-end] [--replace]
       rec tree [EXPERIMENT]
       rec add KIND "TITLE" --in EXPERIMENT --text T [--experiment LABEL] [--by WHO]
                            [--status S] [--answers ID] [--evidence ITEM ...] [--id ID] [--time T]
                            [--quiet]
       rec set ID FIELD=VALUE ... [--quiet]
       rec open
       rec run EXPERIMENT NAME [--note T] [--start T]
       rec end RUN [--status FINISHED|FAILED|KILLED] [--at T] [--metric K=V ...] [--tag K=V ...]
                   [--file PATH[=NAME] ...]
       rec stop RUN ...
       (each but project takes --project P)

The experiments form a tree whose roots are the projects. rec works in the
project --project names, else in the one whose folder holds the current folder
(or the folder at the same place in its git repository's main worktree), and
uses only that project's experiments, runs and records; with no project, it
refuses them, and open prints every project's open records. A --text of -
reads the text from stdin, without its last line breaks: a quoted heredoc
(--text - <<'EOF') needs no escaping. add's --time, run's --start and end's
--at are ISO 8601 times, as "2026-09-10 12:00" or 2026-09-10T12:00, local
unless they end in Z or an offset (2026-09-10T10:00Z, 2026-09-10T12:00+02:00),
as lab.py takes them too. The database is lab.db in $EXPERIMENT_LAB_DATA,
else ~/lab-data.

project NAME makes a project, once, from its folder, --folder (by default the
current git repository's main worktree, else the current folder, but the
current folder when the main worktree holds another project's), with --text,
a one-line description; given again, it changes what is given. --files is the
folder its files page shows (its folder unless given), --views its view files,
run after lab.sql in that order (--views alone clears them). A description
other than the project's own is refused unless --replace.

experiment NAME makes an experiment directly below the project, or below --in
PARENT, with --text, its description (Markdown: what it measures and why);
given again, it moves it below --in, with its runs and records and the
experiments below it, or marks it as a dead end with --dead-end (an idea that
failed; a finding says why) or not with --no-dead-end. NAME and PARENT are in
the project rec works in, or with --move in any project, so that NAME moves to
PARENT's: rec then prints how many runs, records and experiments moved. A
description other than an existing experiment's own is refused unless
--replace, since a new experiment needs a name that no experiment of the lab
has, of at most 32 characters.

tree prints the project's experiments, or those below EXPERIMENT, one per line,
each indented below the one it came from, with [dead end] after those marked
so, then the project's protocol rules, its protocol records not superseded,
each with its text.

add KIND TITLE files a record in the experiment that --in names, which must
exist, or with --in PROJECT in the project itself. KIND is decision, finding,
protocol or question; TITLE is its title, not its id. --text, its text
(Markdown), may not be empty. --experiment gives the label it is shown under
(the --in experiment unless given), --by its author (agent unless given). A new
question is open and any other record closed, unless --status says otherwise
(open, closed or superseded); --answers ID closes the question ID. --evidence
items are run:<run id>, file:<path>, sql:<query over the views> or
record:<id>, the run, record or file existing. A sql: item runs as the record
page runs it and is refused if it fails; each run it returns in a column run
is added as a run: item, so that the record keeps the runs it relied on (none
from an item that returns more than 20). A file: item's file or folder is
copied into the data folder, as evidence/<digest of its content>/<its name>,
and the record cites the copy, so that it shows later what it cited; one over
100 MB is cited where it is, with a warning. A run id in the text that the
evidence does not cite is warned about. --id gives the
record's id (lower-case letters, digits and dashes), else rec makes one from
the title's first words; --time its time, now unless given. add prints the
records it adds or closes, then, if it changed how many of the project's
records are open, how many are; with --quiet, only the id of the record it
adds.

set ID FIELD=VALUE ... changes the record ID's FIELD: kind, title, text, by,
status, experiment, answers or evidence (items separated by ";"). FIELD=-
reads VALUE from stdin, as --text - does, for one FIELD per call. It checks
the evidence and warns as add does, and prints the record, then how many of
the project's records are open, as add does; with --quiet, only its id.

open lists the project's open records.

run EXPERIMENT NAME starts a run, RUNNING, in an existing experiment, for work
that runs outside the Python that logs it, and prints its id. --note is the
run's note, and --start its start, now unless given.

end RUN ends a RUNNING run, FINISHED unless --status says FAILED or KILLED, at
--at, now unless given, which may not be before the run's start. First it
logs its results, as lab.py's log_metrics, set_tags and log_file do: --metric
KEY=VALUE items, each a number, at step 0 and the end's time; --tag KEY=VALUE
items; --file items, each PATH, the file copied under its own name, or
PATH=NAME (split at the last =), copied as NAME. A wrong item is refused
before anything is written.

stop RUN ... stops each RUNNING run whose process logs it in lab.py's with
block, on this host: it sends the process SIGTERM, whose handler stops the
processes it started and ends the run KILLED, waits until the runs have ended,
at most a minute, and prints how each did. A run of rec run has no process that
the lab knows: stop its work, then rec end it.

positional arguments:
  {project,experiment,tree,add,set,open,run,end,stop}

options:
  -h, --help            show this help message and exit
  --project P
exit 0

$ q --help
usage: q [-h] [--project PROJECT | --all] [--max MAX] [--full] [sql]

Runs SQL over the views of the lab's database and prints the result: a line
of column names, then a line per row, cells joined by " | " and not padded.

usage: q [--project P | --all] [--max N] [--full] "SQL"   (SQL from stdin when omitted)
       q [--project P | --all] .views                     (each view and its columns)
       q [--project P | --all] [--max N] .keys            (the keys of the runs)

The database is lab.db in the data folder ($EXPERIMENT_LAB_DATA, else
~/lab-data), attached read-only as the catalog lab with the tables
lab.experiments, lab.runs, lab.params, lab.tags, lab.metrics (every value
logged), lab.files (the files logged for runs) and lab.records. The views are those of experiment_lab/lab.sql, then
those of the view files of the project of the current folder (the one whose
folder holds it or the folder at the same place in its git repository's main
worktree), or of --project; a
statement of a view file that fails is printed on stderr and skipped. lab.sql's
views hold that project's rows only; with --all, they hold every project's and
no view file runs. From a folder no project holds, q needs --project or --all.
Several statements may be given; the rows of each SELECT (DESCRIBE, SHOW,
SUMMARIZE and FROM too) and of the last statement unless it is a COPY are
printed, each result after a line "-- statement N" when there are several, the
same way at any number of rows: a line of column names, at most --max rows
(40), with cells cut at 80 characters unless --full, and a line of their
count. The cell of a result of one row and one column prints whole, with its
line breaks, as in q "SELECT text FROM records WHERE id = '...'". A COPY prints
only what it writes, and when nothing prints, "ok" goes on stderr, so that
COPY (...) TO '/dev/stdout' gives a script the rows alone. An error about a column
that is not found names the views that have it; one about the table params,
tags or metrics, the map column of runs; one about a view that was renamed,
its new name; one about text in params or tags, a cast; a list of candidate
functions is cut to three. .keys lists each key of the tags, params and
metrics of the runs in the view runs, with the number of runs that have it.

positional arguments:
  sql

options:
  -h, --help         show this help message and exit
  --project PROJECT
  --all
  --max MAX
  --full
exit 0
